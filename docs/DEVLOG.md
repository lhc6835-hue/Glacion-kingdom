# 개발 기록 (DEVLOG)

다음 작업을 이어갈 때 이 문서부터 읽습니다. 가장 최근 항목이 맨 위에 옵니다.

---

## v0.3.1 — 세로 화면
- 세로 화면에서는 게임 화면 높이를 가로 폭의 1.25배까지로 묶고(`Engine.resize`), 남는 아래쪽을 조작 패널(`.deck`)로 씁니다. 화면은 최소 240 아트 픽셀 폭, 약 280~330 아트 픽셀 높이라 배경과 나무가 잘리지 않습니다
- 브라우저 테스트 37개(세로 화면 2개 추가)

## v0.3 — 도끼 제단 개편
- 제단 화면을 새로 짰습니다: 룬 제단 무대, 보장 막대, 큰 기도 버튼, 탭 3개
- `ui/GachaFX.js`: 전체 화면 뽑기 연출. 최고 등급에 따라 4단계(tier 0~3)로 세기가 달라집니다. 누르면 단계를 건너뜁니다. 효과음은 `gachaCharge`, `gachaBurst`, `flip`, `flipHi`, `spot`
- 브라우저 테스트 35개

## v0.2 — 시작 화면, 모션, 모바일
- 오프닝 시네마틱을 없앴습니다. 시작 화면을 누르면 바로 플레이합니다(소리 재생 허가 때문에 첫 입력은 필요함)
- 시작 화면 타이틀: 글꼴을 npm의 `@fontsource/cinzel-decorative`, `@fontsource/cinzel`(라틴 부분집합만)로 프로젝트에 넣었습니다. 한글 글꼴(Gowun Batang)은 12MB라 넣지 않고 시스템 명조체를 씁니다
- 나무 크기: `game/TreeShape.js`가 시드별로 높이, 수관 폭, 줄기 굵기, 기울기, 수관 형태를 정합니다. 그림과 HP·목재가 같은 값을 씁니다
- 주인공은 화면 해상도의 별도 캔버스에 그린 뒤 색 보정을 거쳐 합성합니다(`Renderer.drawActor`). 그래서 크기 변형이 부드럽고 픽셀은 각지게 유지됩니다. 모션은 `Player.animate`에 있는 스프링 기반입니다
- 모바일: 터치 버튼(`UI.setupTouch`), 가상 키(`Input.virtual`), 세로 화면 배율 보정
- 테스트: 로직 58개, 브라우저 32개(휴대폰 가로 화면 5개 포함)

## Axenfall v0.1 — 핵심 루프

### 결정 사항
- 사용자 요청에 따라 저장소의 이전 게임(글래시온 왕국, Three.js 탑다운)을 걷어내고 Axenfall로 교체했습니다. 이전 코드는 git 기록에 남아 있습니다(`66d243c` 이전)
- 색감: 맑고 산뜻한 쪽이 아니라 **그늘진 계곡 숲**입니다. 청록 그림자, 이끼 바위, 시냇물에 따뜻한 빛줄기로 대비를 줬습니다
- 에셋: 외부 무료 에셋을 우선하기로 했지만 네트워크 정책으로 사이트가 막혀서, 전부 코드로 생성했습니다([ASSETS.md](ASSETS.md))
- 1차 범위: 핵심 루프를 완성하는 것. 지역 1곳, 전투, 경제, 뽑기, 제재소, 클래스, 저장, 오프닝까지
- 첫 지역 이름은 프롬프트의 Evergreen Haven을 계곡 콘셉트에 맞춰 Evergreen Hollow(상록 계곡)로 바꿨습니다

### 검증
- `node tests/logic.mjs`: 55/55. 데이터 무결성, 판정 구간, 판정별 피해, 방어, 화상, 연쇄 번개, 공허, 클래스 효과, 판매와 구매, 뽑기 확률과 천장, 제재소, 오프라인 상한, 시계 되돌림, 저장과 백업 복구, 마이그레이션
- `node tests/smoke.mjs`(빌드 후): 25/25. 실제 브라우저에서 타이틀, 시네마틱 건너뛰기, 이동, 클릭으로 벌목, 크리티컬 3배, 빗나감, 나무 쓰러짐, E로 상인 열기, 판매, 도끼 구매와 장착, 10회 기도, 제재소 수리와 가공, 클래스 구매, Q 기술, 밤, 새로고침 후 진행 유지, 헤드리스 60fps, 런타임 오류 없음
- `node tests/balance.mjs`: 결과는 [BALANCE.md](BALANCE.md)
